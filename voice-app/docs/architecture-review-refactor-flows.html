1. Make Source Package the real seam

Collapse analysis-output → creation-input mapping into one deep module.

Strong ports & adapters
Files
  • voice-app/backend/services/comic_series_analysis/handoff.py
  • voice-app/backend/services/comic_series_analysis/source_context.py
  • voice-app/backend/services/video_inspiration.py
  • voice-app/backend/services/video_project_memory.py
  • voice-app/backend/services/story_studio.py
  • voice-app/backend/services/video_phase2.py

Problem. Comic analysis, Video Inspiration, Story Studio, and AI Video each translate source evidence into their own prose/source blocks, so source chunking, provenance, stale rules, and output settings leak across seams.

Solution. Deepen one Source Package module that owns evidence, chunk selection, provenance, dependency fingerprint, and task-scoped context for creation modules.

Before
flowchart TB
  CA[Comic analysis package] --> CH[comic handoff.py]
  CH --> SS[story_studio.py]
  VI[VideoAnalysisPackage] --> VIP[video_inspiration.py]
  VIP --> VPM[video_project_memory]
  VPM --> AV[AI Video source blocks]
  SS -.source rules leak.-> AV
  CH -.settings duplicated.-> SS
  VIP -.source block shape.-> AV
  classDef leak stroke:#dc2626,stroke-width:2px,color:#dc2626;
  class CH,SS,VIP,VPM leak;
After
flowchart TB
  CA[Comic adapter] --> SP[Source Package module]
  VI[Video adapter] --> SP
  MS[Manual source adapter] --> SP
  SP:::deep --> ST[Story creation module]
  SP --> VT[Video creation module]
  SP --> MEM[dependency/stale records]
  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a,stroke-width:3px;
Wins
  • locality: source rules concentrate
  • leverage: comic + video adapters
  • interface shrinks for creation
  • stale logic stops leaking
  • tests hit one seam
Deletion test: deleting this module would scatter chunk selection, provenance, and dependency fingerprints back into four workflows. That means the module earns depth.

2. Deepen Story Studio into Story Production

Move creation behavior behind a smaller workflow seam.

Strong in-process
Files
  • voice-app/backend/services/story_studio.py
  • voice-app/backend/routes/story_studio.py
  • voice-app/app/src/components/StoryStudio/StoryStudio.tsx
  • voice-app/backend/services/series_brain.py
  • voice-app/backend/services/series_references.py

Problem. story_studio.py has 4,142 lines and 142 function/class declarations. It owns episode CRUD, creative brief, candidate generation/evaluation/synthesis, master approval, image prompt QA, render state, video handoff, and series update suggestions.

Solution. Deepen a Story Production module: callers ask for episode production outcomes while candidate generation, prompt QA, adaptation state, and video handoff stay internal.

Before: shallow mass
Interface: episode, candidate, score, synthesize, approve, image prompt, repair, render, video handoff, suggestions
Implementation: same concepts repeated as helpers and route actions
After: deep module
Small workflow seam: produce / approve / adapt
Internal implementation: source context, candidate engine, critic, synthesis, panel QA, image adaptation, video handoff, stale propagation
Wins
  • locality: production rules concentrate
  • leverage: UI learns less
  • interface becomes test surface
  • candidate tests stop mocking internals
  • video handoff becomes internal
Risk: splitting files without shrinking the interface only moves complexity. The seam must be around story production outcomes, not helper categories.

3. Turn Video Inspiration into a Video Analysis Pipeline

Separate ingestion/timeline/analysis/rewrite/handoff as internal phases behind one module.

Strong in-process
Files
  • voice-app/backend/services/video_inspiration.py
  • voice-app/backend/services/video_inspiration_runs.py
  • voice-app/backend/routes/video_inspiration.py
  • voice-app/backend/services/video_project_memory.py
  • voice-app/backend/services/video_quality.py

Problem. video_inspiration.py has 3,001 lines and 112 function/class declarations. The same module handles URL/download policy, FFmpeg, STT, frame/shot extraction, visual AI, content analysis, rewrite, script edits, and AI Video project handoff.

Solution. Deepen a Video Analysis Pipeline module so the workflow has locality around phase state, coverage, cancellation, retry, and package creation.

Wins
  • locality: phase state lives together
  • coverage tests hit one module
  • retry/cancel stop leaking

  • FFmpeg becomes adapter detail

4. Split AI Video by workflow, not by helper file

Shrink the external seam that UI and routes must understand.

Worth exploring in-process
Files
  • voice-app/backend/routes/ai_video.py
  • voice-app/backend/services/video_phase2.py
  • voice-app/backend/services/video_projects.py
  • voice-app/backend/services/video_auto_runs.py
  • voice-app/backend/services/video_clip_generation.py
  • voice-app/backend/services/video_rendering.py
  • voice-app/app/src/components/AIVideoAssistant/AIVideoAssistant.tsx

Problem. routes/ai_video.py exposes 136 route handlers, while AIVideoAssistant.tsx has 45 query/mutation hooks. The UI must know series memory, project planning, source blocks, shots, prompts, clips, provider sessions, render jobs, packages, and auto-runs.

Solution. Deepen workflow modules around project creation, prompt generation, provider execution, and delivery, then expose workflow snapshots instead of every internal state transition.

Before

  UI[AIVideoAssistant UI] --> R[ai_video route: 136 handlers]
  R --> MEM[series memory]
  R --> PLAN[planning]
  R --> SHOT[shots/prompts]
  R --> PROV[provider sessions]
  R --> CLIP[clip generation]
  R --> REN[render]
  R --> PKG[package]
  UI -.polls many states.-> CLIP
  UI -.polls many states.-> REN
  classDef leak stroke:#dc2626,stroke-width:2px,color:#dc2626;
  class UI,R leak;
After
flowchart TB
  UI[AI Video workspace UI] --> WF[AI Video Workflow module]
  WF:::deep --> P[project planning module]
  WF --> G[prompt/shot module]
  WF --> E[provider execution module]
  WF --> D[delivery module]
  E --> AD[Veo/browser adapter]
  D --> REN[render adapter]
  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a,stroke-width:3px;
Wins
  • interface shrinks for UI
  • locality: polling rules concentrate
  • provider adapter stays internal
  • render tests hit delivery seam
  • route file stops being map
Worth exploring because some route split can be mechanical. The deeper refactor is the workflow seam; moving handlers alone gives low leverage.

Top recommendation

Start with Source Package as the seam.

It touches all four flows and satisfies the adapter test: comic analysis and video analysis are two real adapters feeding creation. Once this seam is deep, Story Studio and AI Video can be refactored behind smaller workflow modules without carrying source/provenance/stale complexity everywhere.
